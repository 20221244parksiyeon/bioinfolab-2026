# 나의 Bash 치트시트

## 1. 자주 사용할 명령어

| 명령어 | 기능 | 실제 사용 예시 |
|---|---|---|
| `ls` | 파일/폴더 목록 확인 | `ls src` |
| `cd` | 폴더 이동 | `cd lab05` |
| `grep` | 원하는 문자열이 있는 줄 검색 | `grep "^seqs.fasta" seq_counts.txt` |
| `grep -c` | 조건에 맞는 줄의 개수 계산 | `grep -c "^>" data/seqs.fasta` |
| `grep -v` | 조건과 일치하지 않는 줄 출력 | `grep -v "^>" data/seqs.fasta` |
| `wc -l` | 줄 수 계산 | `ls \| wc -l` |
| `cut` | 원하는 필드만 추출 | `grep "^seqs.fasta" seq_counts.txt \| cut -f2` |
| `chmod +x` | 실행 권한 부여 | `chmod +x src/countseq.sh` |

## 2. 꼭 기억할 Bash 문법

- `$1`, `$2` : 첫 번째, 두 번째 명령행 인자
- `$#` : 입력된 인자의 개수
- `$?` : 직전 명령의 종료 상태 (`0`은 성공)
- `|` : 앞 명령의 출력을 뒤 명령으로 전달
- `>` : 파일을 덮어써서 저장
- `>>` : 기존 파일 뒤에 추가
- `$(명령어)` : 명령 실행 결과를 값으로 사용
- `*` : 0개 이상의 모든 문자

## 3. 내가 실수했던 것

1. 변수 대입 시 `DIR= $1`처럼 공백을 넣음 → `DIR=$1`로 작성한다.
2. `for` 반복문 마지막에 `done`을 빼먹음 → `for-do-done` 구조를 확인한다.
3. `$1`을 사용하는 스크립트에 인자를 주지 않음 → 실행할 때 필요한 인자를 확인한다.
4. 출력 결과를 다시 터미널 명령어로 입력하지 않는다.

## 4. 스크립트 만드는 5단계

1. 먼저 터미널에서 명령어를 직접 실행해 본다.
2. 동작하는 명령어를 `.sh` 파일에 넣는다.
3. 파일명 등 바뀌는 값을 변수로 만든다.
4. `$1`, `$2` 등 명령행 인자를 받아 재사용할 수 있게 만든다.
5. 인자 개수, 파일 존재 여부 등을 검사하고 오류 메시지와 종료 상태를 설정한다.

## 5. 자주 쓰는 반복문

```bash
for F in data/*.fasta
do
    COUNT=$(grep -c "^>" "$F")
    echo "$F : $COUNT"
done
